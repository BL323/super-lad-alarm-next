# Super Lad Alarm: notes for Claude

- The spec is `initial-build-brief.md`. Its section 2 decisions are fixed; build in the section 11 stage order and update the README "Status" table and "Decisions" list as you go.
- Mobile landscape first. Check changes at 1920×1080, 1280×720, 844×390 and 640×360 with the `dev` launch config (`.claude/launch.json`).
- All tunable numbers go in `src/config.js`; texture/animation keys in `src/assets.js`; scene keys in `src/scenes/keys.js`. Use `addText()` from `src/ui/text.js` for all text.
- Runtime dependency is `phaser` only, dev dependency `vite` only. Don't add packages without a clear reason.
- Phaser's `scale.refresh()` uses a cached parent size; call `scale.getParentBounds()` first (see `src/systems/Scaling.js`).
- The Player reads only `VirtualInput.state`, never raw keys/pointers. All deaths go through `player.die()`.
- Touch buttons cover the bottom corners: keep spawn points and level start/end content clear of them.
- Low bridges are `girder` tiles (`bridge()` in `scripts/levels/lib.mjs`): solid ceilings the validator never treats as ground or ledges. `config.js` is importable from Node (no `window`/Vite env at import), so the validator and builders read tuning from it; keep it that way.
- Test flags: `?touch` forces on-screen buttons on desktop; `?debug` (dev only) shows bodies and player state.
- Phaser static bodies: `refreshBody()` resets the body size to the sprite, so call `body.setSize()` after it.
- Story/theme: `docs/story.md`; the agreed mapping is in the README "Story and theme" section. Title stays "Super Lad Alarm".
- Levels are generated: one builder per level in `scripts/levels/` (shared helpers in `lib.mjs`), then `npm run build:levels` (it validates too). Don't hand-edit the JSON. Register levels in `src/level/levels.js` in crawl order; `npm run validate:levels` checks the registry against the files.
- Browser testing: the preview pane throttles requestAnimationFrame, so for gameplay tests call `__game.loop.sleep()` and step frames manually with `__game.step(t, 1000/60)`. Tweens don't advance under manual stepping; check those with the loop running. `scene.restart()` keeps `scene.events` listeners, so reload the page between scripted runs.
- HUD and other crisp text: `addPixelText()` (bitmap font; upper case, digits and `+-./:!'` only). `Phaser.GameObjects.RetroFont.Parse` returns the full cache entry, so pass it straight to `cache.bitmapFont.add`.
- Collected items are destroyed when their pop tween finishes, so under manual frame stepping check `item.collected`, not group size.
- Characters are Naylor's outfits, looks only (`CHARACTERS` in `src/assets.js` + `PLAYER_LOOKS` in `src/art/placeholders.js`); default is `casual`. Never give them different movement without updating the level validator.
- Scene flow: Menu → CharacterSelect → LevelSelect → NextStop → Game(+UI) → Complete → NextStop … → CrawlComplete. Selected lad lives in `registry.get('characterId')`, the crawl (per-level results) in `registry.get(CRAWL_KEY)`; the menu clears it.
- Listeners on `scene.events` / `game.events` / `scale` must be removed on SHUTDOWN (emitters outlive restarts).
- Runs are timed, not scored: no points, no saved best, no pause (owner's decision, overrides the brief). Final time = clock + 2 s per missed pint − bonus `timeBonusMs`; see `finalTime()` in `src/systems/GameState.js`. Don't add localStorage.
- Portrait freeze uses `game.loop.sleep()`/`wake()` (src/systems/mobile.js); always `loop.resetDelta()` before `wake()` or the clock jumps.
- Boss: `src/systems/BossArena.js` + `src/entities/Conductor.js`, tuned by `BOSS.first` (4 stomps) / `BOSS.final` (6) in config (the boss object's `tuning` property picks one; read per-phase values with `conductor.perPhase()`). Level 3 has the first fight (cols 114–133), level 6 the final one (cols 112–131, six stomps, the double dash: `turn` state, `doubleDashChance`, `doubleDashDizzyMs`; the Conductor's `random` argument lets tests force it). The intro line is the tuning's `introText`. Any player death during the fight resets it. Camera `pan()` needs long ease names (`'Sine.easeInOut'`); tweens accept short ones.
- Phaser Containers already have `x, y, z, w` (Transform): never store sizes as `this.w`/`this.h` on a Container (`setPosition()` resets `w` to 0).
- Listeners on `scene.events` 'update' can fire once more in the frame their owner is destroyed (snapshot emit); guard with `if (!this.scene) return`.
- The finish is a pub door: put the `finish` object in the same column as its `pub` decor.
- Thrown things go through `Lobber` (`src/systems/Lobber.js`): the boss's tickets and the Black Bear's beer mats (`Throwers`, `THROWERS` in config). Throwers only throw at a player on the street in range, so rooftops are safe.
- Crumbling crates (`crumble()` objects, `src/systems/Crumbles.js`) bridge gap tiles only and all reset on player respawn. Level crossings (`crossing()`, `src/systems/LevelCrossing.js`): only the approach arm is ever solid, and only while the player is still before it; tuning in `CROSSING`.
- If the preview pane is hidden, requestAnimationFrame doesn't run at all: drive boot and play with `__game.loop.sleep()` + `__game.step()` (Boot → Menu needs steps too).
- Sound: effects are synthesised in `src/audio/sfx.js` and built into the audio cache at boot (`Audio.registerSynthSounds`). Play with `Audio.play(key)`; a real file loaded under the same key replaces the synth. Don't add audio packages.
- Phones scale to fill (`SCALING.fillOnTouch`); desktop keeps integer scaling. Full screen is only ever requested from a tap (`src/systems/fullscreen.js`); iPhone gets the Home Screen hint instead. Icons come from `npm run build:icons` (the game's pint art); don't hand-draw them.
- The game width varies (320–400, height fixed at 180): read `scene.scale.width` / `cam.width`, never `GAME_WIDTH` (that's only the narrowest view). Static screens call `restartOnWidthChange()` (`src/ui/relayout.js`); in-game UI re-lays out on the scale RESIZE event.
- Moving platforms (`mover()` in `lib.mjs`, `src/systems/MovingPlatforms.js`, `MOVERS` in config): one-way immovable decks steered by velocity on the physics `worldstep` event. Riders are only carried if the deck's `friction.x` is 1 (physics groups default it to 0). One mover per gap; the validator checks the jump on at its near end and off at its far end. Swans (`swan()`, `src/systems/Swans.js`) are deadly and can't be stomped. `river()` and `trench()` draw the water/mud and add the deadly zone.
- Level layout traps the validator can't see: a suitcase/luggage just before a gap (a full jump over it lands in the gap) and glass under a low bridge (the short hop window is ~80 ms). Run an autopilot over new train sections.
- Night theme: `THEMES.night.lampsLit` puts a `LAMP_GLOW` glow round every `lamp` decor.
- Level 5 pieces: `autoscroll()` (one per level, `src/systems/AutoScroll.js`), `awning()` (`src/systems/Awnings.js`; bounces through `player.bounce(v, { fixed: true })`), `gull()` (`src/systems/Gulls.js`), the `ferry` mover, and the `weather: 'rain'` map property (`src/systems/Weather.js`). The validator knows each one's rules; keep their tuning in `AUTOSCROLL`, `AWNINGS`, `GULLS`, `MOVERS`, `RAIN`. HUD messages from any system: `scene.events.emit('toast', text)`.
- Scripted browser tests: don't clear `controls.state.jumpPressed` inside a `controls.update` override (it runs before the player reads it); set it for one step, then clear it. Stop stepping once `gameState.completed`, or the Complete scene destroys the player under you.
- Ground for the Player is `body.blocked.down` (tiles) or a collider calling `player.standOn()` (decks, crumbling crates, awnings, the boss's cap). Never test `body.touching.down` for ground: overlaps (pints, hazards, zones) set it too.
- Scenes are reused objects: reset any per-visit flag (`leaving`, `going`, …) in `create()`, or the second visit inherits it.
- Crumbling crates need a gap tile on both sides (they shake sideways), and a 1+2+1 crumble gap (4 tiles) is a trap: a full jump from the edge lands just short of the far side. Use 1+1+1, 1+3+1 or 1+4+1.
- High roads: crate stair top at col X, row 7; rooftop (`roof(…, 5)`) from col X+2 over houses (each 4 tiles, centred on its column). Keep hazards out of the landing spot off the end of a roof run, and stairs out of any thrower's range (it must be flat street).
